# HUD照準の黒画面への互換修正

EOSの「ヘレナの釘」に内蔵された `scope_eos_eh_72_hud_sight` はscope=true/sight=falseですが、ocular自身にcubeがなく、子の発光HUD部品が9枚の面を持ちます。PiPの物理レンズ用の遮蔽処理には適さない構造です。

銃IDによる例外ではなく、光学ocularが「空の親ノード＋描画面がすべて発光する子孫」の場合に、アタッチメント全体をTaCZ標準描画に戻します。発光は親からの継承も考慮。部品の一時的なvisibleやADS進行度では判定せず、モデル単位でキャッシュします。

- PiPの黒い遮蔽・照準線置換・追加ワールド描画を行わない。
- モデル倍率固定と背景ズーム抑止からも除外し、TaCZの倍率を使う。
- 通常の非発光レンズ面、非発光の子部品、混在構造、空のモデルはこの判定で除外しない。
- HUD型へのPiP対応を追加したのではなく、黒画面を避けるための標準描画フォールバック。

検証: Javaの純粋な構造判定テスト6ケース、実際のEOSパックのocular構造とTaCZの発光名の解釈を確認。Gradle build成功。ユーザーからヘレナの釘の問題解消と、確認した範囲の通常スコープへの影響なしの報告あり。倍率切替やシェーダーON/OFFなど全組み合わせの確認を意味するものではありません。他パックの発光レンズ構造でも安全側の標準表示になる可能性はあります。
