# Distant Horizons互換処理（2026-10-21）

## 対象と検証状況

Minecraft 1.20.1 / Forge 47.4.10 / Java 17 / TaCZ 1.1.8-hotfix2。
任意MODのうちEmbeddium 0.3.31、Oculus 1.8.0の条件は変更していない。

| DH | 判定 | 静的検査 | 今回の起動・実画面 |
| --- | --- | --- | --- |
| 2.2.1-a | 旧描画経路 | 合格 | ユーザー確認待ち（旧実装の利用実績あり） |
| 3.3.0 | 新OpenGL経路 | 合格 | ユーザー確認待ち |
| 3.3.2 | 新OpenGL経路 | 合格 | ユーザー確認待ち |
| 3.3.3 | 新OpenGL経路 | 合格 | ユーザー確認待ち |
| 将来の3.3.0以上の正式版 | 同じ構造検査に合格した場合のみ許可 | 未取得・未検証 | 保証なし |

2.3～3.2系やプレリリースは対象外。DHは任意依存で、未導入でも使用できる。
ここでいう合格は実JARのクラス・メソッド・描画状態フィールドの検査であり、ゲーム起動や描画結果の保証ではない。

## 変更点

- `LodRenderer.setupGLStateAndRenderObjects`／`cleanup`が存在する旧経路だけに旧Mixinを適用。3.3系や構造不一致の版に旧Mixinを適用しない。
- 3.3系ではフレームバッファ管理が`GlDhMetaRenderer`へ移動。登録されたOpenGLレンダラーの実体を取得し、メイン画面とPiPで専用の色・深度・ポスト処理バッファを切り替える。
- `ClientApi.RENDER_STATE`、`RENDER_PARAMS`、最終行列を含む可変オブジェクト、公開テクスチャID、ラッパーの描画先を復元する。
- SSAO・霧・遠景フェード・通常地形フェードのバッファも分離。メイン側資源や共有シェーダーを破棄しない。
- **PiP内DHのTAAを標準化**。履歴テクスチャ・ping-pong状態・前回の行列／カメラ位置・ジッター番号を通常画面から分離する。通常画面のTAAとシェーダーパック側のAA設定は変更しない。
- Oculusの既存の上書きレジストリ退避・復元を維持。DH単体とOculus併用は別々に確認する。
- 将来の構造不一致は警告を一度出してPiPを無効化する。構造検査で検出できない動作変更や、DH・Oculus自身の互換不具合まで防ぐ保証はない。

## 実画面確認（ユーザー担当）

同じPiP JARを全4版で使う。各テストでDHのJARを1本だけ入れ、Minecraftを完全終了してから入れ替える。DHのデータベースは後方互換を保証できないため、**ワールドと設定をコピーした別インスタンスを版ごとに使い、3.3系で開いたワールドを2.2.1-aへ戻さない**。

1. 最初はDH＋TaCZ＋PiPで、起動・ワールド参加・通常の遠景表示。
2. スコープADSで遠景が表示されること、構え解除で通常画面が崩れないこと。
3. 揺れ・倍率切替・リロード・持ち替え。
4. PiP解像度75%／100%、ウィンドウサイズ変更、水面・透明部分、ワールド再入場。
5. 必要ならEmbeddium＋OculusでシェーダーOFF／ONを追加確認。

報告にはDH版、Oculusの有無、シェーダー名、症状、`logs/latest.log`を添える。
問題があれば既存の2.2.1-a環境のコピーへ戻せるよう、元のPrism環境は変更していない。

## 再現用のコード検査

### PiP内TAAの標準化（2026-10-23）

ユーザーの比較ではFPSに大きな差が見られなかったため、PiP専用TAAを標準化し、比較用設定`performance.pipDhTaa`と表示・翻訳を削除した。旧設定値が残っていても参照しない。対象はDH 3.3系・シェーダーOFF・DH自身のアンチエイリアスONの組合せ。DH側のAAを強制的に有効化する変更ではない。DH 2.2.1-aとシェーダーパックのAA経路は変更しない。

確認項目は静止時の遠景の輪郭、視点移動時の残像、倍率変更・ADS解除／再開・持ち替え・PiP解像度変更で古い映像が残らないこと。FPSに差がないという報告は追加負荷ゼロの保証ではない。

履歴はPiPを更新したフレームだけ進む。倍率／投影・設定・ワールド変更、ADS再開、長い更新中断時に無効化。初回／無効化後は現在のDH色画像を履歴入力に使い、未初期化テクスチャをサンプリングしない。通常画面への状態復元は外側のfinallyで行う。TAA用バッファはPiP専用で保持し、リサイズまたは切断時に解放する。

ビルド・実JAR構造検査・CPU側の履歴分離テスト済み。全対象版・描画条件での実画面検証は継続中。

### 3.3.3・シェーダーOFFでの銃の点滅（2026-10-21）

録画でADS時に銃全体が断続的に消えることを確認。3.3.3実JARではシェーダーOFF時に逆深度を使い、`glClearDepth(0)`へ変更する一方、DHの`GLState`は深度比較関数を戻してもクリア値を保存・復元しない。PiP更新後の手持ち描画前の深度クリアへ値が漏れる経路がある。

PiP描画前（ターゲット生成・リサイズ前）の`GL_DEPTH_CLEAR_VALUE`を保存し、例外時も含め`finally`で復元するよう変更。通常深度の1へ固定せず、呼び出し元の値を保持する。実ゲームで点滅が解消したかはユーザーの再確認待ち。

再確認は3.3.3のシェーダーOFFでADS・持ち替え・リロード、PiP FPS制限の変更。続いてシェーダーONと3.3.0／3.3.2で退行がないかを確認する。

`tools/Test-DhCompatibility.ps1 -JarPaths <各DHのJARパス>`（JAVA_HOME=Java 17）。
ASM／LWJGLの検査用クラスパスはビルド済みGradleキャッシュから取得する。ゲームやGLコンテキストは起動しない。

- 実JARの旧／新構造、DH未導入、フィールド欠落による拒否、正式版番号の判定。
- 旧／新バッファの120回切替、例外時復元、PiP資源だけの解放。
- 旧経路のサイズ変更、可変なfinalパラメーターの復元。
